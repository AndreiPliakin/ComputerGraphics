Теоритическая часть.

1. Модель RGB
RGB (Red, Green, Blue) — аддитивная цветовая модель, в которой цвет формируется путём сложения трёх базовых цветов: красного, зелёного и синего. Каждый канал принимает значения от 0 до 255.

Модель применяется в устройствах, излучающих свет: мониторах, телевизорах, камерах.

2. Модель CMYK
CMYK (Cyan, Magenta, Yellow, Key) — субтрактивная модель, используемая в полиграфии. Значения компонент — от 0 до 1. Цвет формируется вычитанием красок из белого:

3. Модель HSV
HSV (Hue, Saturation, Value) — цилиндрическая модель, интуитивно понятная человеку:

H — цветовой тон, 0–360°,
S — насыщенность, 0–1,
V — яркость, 0–1.

Формулы преобразования:

1. RGB в CMYK
Нормализация: r = R/255, g = G/255, b = B/255.

K = 1 − max(r, g, b)

Если K = 1, то C = M = Y = 0.
Иначе:
C = (1 − r − K) / (1 − K)
M = (1 − g − K) / (1 − K)
Y = (1 − b − K) / (1 − K)

2. CMYK в RGB
R = 255 · (1 − C) · (1 − K)
G = 255 · (1 − M) · (1 − K)
B = 255 · (1 − Y) · (1 − K)

3. RGB в HSV
max = max(r, g, b)
min = min(r, g, b)
delta = max − min

V = max

S = 0, если max = 0; иначе S = delta / max

H:
если Δ = 0, то H = 0
если max = r, то H = 60 · ((g − b) / delta mod 6)
если max = g, то H = 60 · ((b − r) / delta + 2)
если max = b, то H = 60 · ((r − g) / delta + 4)

4. HSV в RGB
C = V · S
X = C · (1 − |(H / 60) mod 2 − 1|)
m = V − C

Номер сектора k = ⌊H / 60⌋. По нему выбирается комбинация (R1, G1, B1):

k | R1 | G1 | B1
0 | C | X | 0
1 | X | C | 0
2 | 0 | C | X
3 | 0 | X | C
4 | X | 0 | C
5 | C | 0 | X

Итог:

R = 255 · (R1 + m)
G = 255 · (G1 + m)
B = 255 · (B1 + m)

Архитектура

Приложение построено по принципу разделения данных и интерфейса.
Модели (RGB, CMYK, HSV) — простые классы, хранящие значения компонент.
На основе моделей созданы функции преобразования между цветовыми моделями.
ColorState — хранилище текущего цвета. Хранит все три представления одновременно и обеспечивает их согласованность.
MainWindow — связывает виджеты интерфейса с состоянием.

Интерфейс

Окно приложения содержит:

Превью текущего цвета — большая цветная область сверху.
Панель RGB: три слайдера (0–255), три поля ввода.
Панель CMYK: четыре слайдера (0–100), четыре поля ввода (0–1).
Панель HSV: слайдер H (0–360) и S, V (0–100), соответствующие поля ввода.
Палитра из 18 кнопок с готовыми цветами.
Кнопка «Random color» в каждой панели.

Таким образом реализованы 3 способа ввода для каждой из моделей и общий способ выбора одного из 18 стандартных цветов

Логика обработки изменений

Все изменения в интерфейсе происходят нижеуказанным способом.

Слайдеры. Когда пользователь двигает слайдер, срабатывает соответствующий обработчик. Он через находит, какой именно слайдер изменился, и обновляет только парный ему спинбокс — чтобы значения совпадали. Обновление спинбокса через setValue эмитит сигнал valueChanged, который вызывает уже обработчик спинбокса — и дальше идёт полный цикл пересчёта.

Спинбоксы. Обработчик спинбокса собирает значения со всех полей своей модели, создаёт объект RGB/CMYK/HSV и передаёт его в ColorState.

ColorState. Сохраняет ту модель, которую задал пользователь, без изменений, а две другие пересчитывает через функции преобразования из conversions.py. Это важно: обратный перевод, например, может дать не исходные значения, поэтому исходная модель хранится точно.

update_ui. Центральный метод обновления. При вызове раскидывает значения из ColorState во все слайдеры и спинбоксы, перекрашивая нужные обьекты соответствующим актуальным цветом. Для защиты от рекурсивного вызова имеет специальный флаг занятости self.updating

Кнопки палитры и Random сразу вызывают update_ui.
